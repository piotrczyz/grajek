# Offline-capable installable app skeleton — Plan Brief
Full plan: `context/changes/szkielet-aplikacji-offline/plan.md` · request text: `change.md` ·
roadmap slice F-01: `context/foundation/roadmap.md`

## What & why
Roadmap foundation F-01: the first code of Grajek. A pupil can add the app to
the home screen on Android and iOS and open it offline, landing on a Polish,
child-friendly welcome screen "Grajek". It also fixes the on-device storage
contract and the static build, so S-01 (Profil i instrument) starts on a
working base.

## Starting point
Greenfield: only `context/` documents. Stack declared in
`context/foundation/tech-stack.md` (React + TS + Vite + vite-plugin-pwa,
Tailwind, IndexedDB contract, Vitest, Playwright, pnpm). Deploy target is the
only open stack question and this change does not depend on it.

## Desired end state
`pnpm build` → host-agnostic `dist/`; Chromium reports the app installable;
iOS gets apple-touch-icon and standalone meta tags; after one online visit the
app reloads offline; `src/storage/` offers a tested, platform-neutral contract
(IndexedDB + memory) with no product data.

## Complexity
MEDIUM — greenfield scaffold with a dozen new dependencies, a service worker
and two test runners; behaviour is small but cross-platform PWA details
(iOS tags, offline reload, installability) need care. No migration, no
security boundary.

Skipped: rs-research (no code exists yet; the stack and constraints are in
tech-stack.md, PRD and ADRs) and rs-frame (the request states an outcome, not
a cause or a fix) — Jev unavailable (dry mode), decided by the planner.

## Scope
In: toolchain, welcome screen, manifest + icons + iOS tags, service worker and
offline reload, storage contract with tests, README publishing notes.
Out: any product feature, product data, push/notifications, deploy target, CI,
install/update prompts, splash images, dark mode, native packaging.

## Architecture / Approach
Client-only SPA; `vite-plugin-pwa` injects the precache manifest into our
`src/sw.ts`; components will reach storage only through `src/storage/`.

## Open risks & assumptions
- iOS behaviour is verified manually only (criterion 2.6).
- Contract shape may grow in S-01 (e.g. queries by index); extension, not a break.
- No `decision-to-verify` guards.

## Success criteria (summary)
`pnpm lint`, `typecheck`, `test`, `build`, `test:e2e` pass; E2E proves
installability (Chromium), iOS tags and an offline reload; storage suite passes
on both implementations; manual install on a real Android phone and iPhone.
